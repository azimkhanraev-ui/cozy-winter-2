# Решения (DECISIONS)

Сюда записываются решения, принятые без вопросов к заказчику.

## Окружение
- **Node.js на машине не был установлен**, а `winget install OpenJS.NodeJS.LTS` завис на загрузке (сеть ~10–20 КБ/с) и завершился с ошибкой. Для разработки использован Node из VS Code (`Code.exe` с `ELECTRON_RUN_AS_NODE=1`, Node v24) и npm 12, скачанный отдельно (шимы в `%LOCALAPPDATA%\cozy-tools`). Пользователю для `npm start` нужен обычный Node.js LTS.
- **Electron зафиксирован на 45.4.1**: его zip уже лежал в `%LOCALAPPDATA%\electron\Cache`, иначе пришлось бы качать ~150 МБ.
- `scripts/start.mjs` удаляет `ELECTRON_RUN_AS_NODE` из окружения перед запуском Electron, иначе он стартовал бы как Node.

## Сборка
- esbuild (без vite): main/preload → CJS, рендереры → IIFE. Типы проверяет `tsc --noEmit` (`npm run typecheck`).
- Зависимостей в рантайме нет, только devDependencies: electron, electron-builder, esbuild, typescript, vitest.

## Архитектура
- `src/sim/` — чистый TS: ГПСЧ/шум, ветер, снегопад, высотная карта, сцена. Без DOM и Electron, покрыт vitest.
- `src/render/` — Canvas 2D: спрайты (offscreen canvas), снег на земле, хлопья.
- `src/main/` — Electron: окна, трей, настройки, IPC.
- `src/ui/` — рендерер-страницы (оверлей, настройки).
- `src/shared/` — схема настроек и типы IPC (чистые, используются обеими сторонами).
- Фиксированный шаг симуляции 1/60 с; рендер может идти на 30 или 60 FPS.

## Оверлей
- Окно = `workArea` монитора (без панели задач). Если `workArea` совпадает со всем экраном (панель скрыта), высота уменьшается на 1 px, чтобы Windows не считал окно полноэкранным. Опция «Земля = низ экрана» берёт `bounds` минус 1 px.
- `focusable:false`, `skipTaskbar`, `alwaysOnTop('screen-saver')`, `setIgnoreMouseEvents(true,{forward:true})`.
- При смене мониторов/DPI окна не пересоздаются, а получают новые границы; снег пересэмплируется на новую ширину.
- Тестовый режим (`--scenario`, `--shot-after`) не берёт single-instance lock и может работать с отдельным профилем `--user-data=...`, чтобы не трогать настройки пользователя.

## Настройки
- `%APPDATA%\CozyWinter2\settings.json`. Запись атомарная (tmp → rename), предыдущая версия → `.bak`.
- Повреждённый файл переименовывается в `settings.json.corrupt-<время>`, затем берётся `.bak`, иначе значения по умолчанию.
- Санитайзер отбрасывает неизвестные ключи, исправляет типы, ограничивает диапазоны.

## Снег (этап 2)
- Высотная карта: колонка 2 px. Скрытый рельеф (шум + бугры + камни) виден только под снегом: видимая высота = снег + рельеф·smoothstep(0..4 px снега). Так голые камни не «торчат» прозрачными буграми.
- Поле неравномерности: низкочастотный fbm + 2–5 гауссовых «зон намётов» + 1–3 «проплешины», нормировано к среднему 1. Множитель накопления = lerp(1, поле, «Неравномерность»).
- Предел высоты мягкий: множитель 1 − (h/cap)², cap тоже немного зависит от поля.
- Осыпание: пары соседних колонок, перекладывание снега с верхней на нижнюю, пока перепад > tan(угла)·2 px. Основа не двигается → объём сохраняется точно.
- Ветер: проход по колонкам по ветру с «горизонтом тени» (11°). В тени (за буграми, шарами, декором — массив `obstacle`) переносимый снег оседает, на открытых местах рыхлый слой эродирует, наветренные склоны сильнее. Снег, вынесенный за край экрана, теряется (унесён).
- Свежий снег рыхлый (его переносит ветер), с постоянной времени ~150 с уплотняется и теряет 25% объёма.
- Тест-сценарий «60 с ускоренной симуляции» = 60 с × 20 = 20 минут снегопада, промотанные без рендера.
- Темп накопления: `DEPOSIT_K = 0.35` площади хлопья на осевшую снежинку; по умолчанию сугробы растут заметно за 10–30 минут.
- Колпак высоты зависит от поля плавно (`f/(f+1.2)`), без жёсткого clamp — иначе вершины сугробов превращались в плато.
- Число зон намётов/проплешин считается по плотности на ширину (≈1 на 480/560 px), а не «на 1920 px»: на узких экранах тоже есть разнообразие.
- Эрозия ветром ≈10%/с рыхлого слоя при сильном ветре: первая версия (≈80%/с) за 10 минут метели сдувала весь снег за край экрана.
- Снежная пыль с гребней — редкие мягкие размытые пятна, вытянутые по ветру (не больше ~220 частиц).
- Слой земли растеризуется программно (`willReadFrequently`) не чаще 5 раз/с: снег копится медленно, а сотни мелких команд на GPU стоили дорого.
- Дальние слои снега рисуются на отдельном холсте через кадр (двигаются < 1 px за кадр).

## Производительность (замер, i5-1135G7 / Iris Xe, 1920×1030, scripts/cpu-breakdown.ps1)
| режим | CPU всей машины (8 потоков) |
|---|---|
| пустой кадр 60 FPS (база Electron + композиция) | 2.0–2.8 % |
| снег по умолчанию, 60 FPS | 5.6–6.2 % |
| снег по умолчанию, 30 FPS | 2.5–3.0 % |
- Симуляция стоит 0.15 мс на шаг (< 1 % ядра) — почти всё уходит на отрисовку и композицию полноэкранного прозрачного окна в GPU-процессе Chromium.
- Пробовали и отвергли: `desynchronized` canvas (хуже, 8.2 %), пакетная отрисовка дальних хлопьев через Path2D (хуже вдвое: тесселяция путей в GPU-процессе).
- **Решение:** по умолчанию оставлено 60 FPS (плавность — основная цель), что на этом ноутбуке чуть выше 5 %. Режим 30 FPS укладывается в 3 %. На этапе 9 режим экономии будет автоматически переключать на 30 FPS (батарея/полноэкранные приложения).

## Проверки
- `--tray-check` нажимает реальные пункты меню трея (пауза, настройки, смена режима) и проверяет результат.
- Снимок рабочего стола делается через `desktopCapturer` (`--desktop-shot`): GDI BitBlt (даже с CAPTUREBLT) не видит прозрачные DirectComposition-окна Electron — первая проверка ошибочно показала «оверлея нет». Такие снимки содержат личный рабочий стол и в git не попадают (`tests/shots/desktop*.png` в .gitignore).

## Этап 3: уборка снега
- Снег — карта высот, поэтому инструмент-круг «срезает» всё, что выше нижней кромки круга (дыру в середине колонки сделать нельзя).
- Лопата: 55% снега толкается вперёд по ходу (валик в конце), 45% бросается «через плечо» за начало хода — так получаются валики по обе стороны чистой полосы. Объём сохраняется точно; у края экрана снег уходит на другую сторону.
- После хода лопаты — мгновенная локальная лавина (`settleAround`): без неё на месте валика несколько секунд стоял вертикальный столб (замечено на скриншоте, хотя числовые проверки проходили; в selftest добавлена проверка угла откоса).
- Снегодув уносит снег частицами-«носителями», которые возвращают объём туда, где упадут (за край экрана — теряется). Тепло растапливает (объём исчезает) с паром и каплями.
- «Очистить всё» — фронт порыва ветра проходит по экрану ~1.6 с.
- Undo/Redo: история (40 шагов) живёт в каждом окне-мониторе; main помнит порядок правок и отправляет Ctrl+Z/Ctrl+Y нужному окну.
- Оверлей никогда не получает фокус: Esc, Ctrl+Z/Y и цифры регистрируются как глобальные клавиши **только пока открыт интерактивный режим**, затем снимаются.
- Двойной клик определяется вручную (два нажатия < 450 мс): окно без фокуса получает dblclick ненадёжно.
- Док висит над сугробами (а не на панели задач), иначе закрывал бы снег и перехватывал движения инструментов у земли.
- Тесты ввода (`--input-test=…`) двигают настоящую мышь через `webContents.sendInputEvent`: клик по вкладке-снежинке → кнопка инструмента в доке → перетаскивание по снегу.
