# Решения (DECISIONS)

Сюда записываются решения, принятые без вопросов к заказчику.

## Окружение
- **Node.js на машине не был установлен**, а `winget install OpenJS.NodeJS.LTS` завис на загрузке (сеть ~10–20 КБ/с) и завершился с ошибкой. Для разработки использован Node из VS Code (`Code.exe` с `ELECTRON_RUN_AS_NODE=1`, Node v24) и npm 12, скачанный отдельно (шимы в `%LOCALAPPDATA%\cozy-tools`). Пользователю для `npm start` нужен обычный Node.js LTS.
- **Electron зафиксирован на 45.4.1**: его zip уже лежал в `%LOCALAPPDATA%\electron\Cache`, иначе пришлось бы качать ~150 МБ.
- `scripts/start.mjs` удаляет `ELECTRON_RUN_AS_NODE` из окружения перед запуском Electron, иначе он стартовал бы как Node.

## Сборка
- esbuild (без vite): main/preload → CJS, рендереры → IIFE. Типы проверяет `tsc --noEmit` (`npm run typecheck`).
- Зависимостей в рантайме нет, только devDependencies: electron, electron-builder, esbuild, typescript, vitest.

## Архитектура
- `src/sim/` — чистый TS: ГПСЧ/шум, ветер, снегопад, высотная карта, сцена. Без DOM и Electron, покрыт vitest.
- `src/render/` — Canvas 2D: спрайты (offscreen canvas), снег на земле, хлопья.
- `src/main/` — Electron: окна, трей, настройки, IPC.
- `src/ui/` — рендерер-страницы (оверлей, настройки).
- `src/shared/` — схема настроек и типы IPC (чистые, используются обеими сторонами).
- Фиксированный шаг симуляции 1/60 с; рендер может идти на 30 или 60 FPS.

## Оверлей
- Окно = `workArea` монитора (без панели задач). Если `workArea` совпадает со всем экраном (панель скрыта), высота уменьшается на 1 px, чтобы Windows не считал окно полноэкранным. Опция «Земля = низ экрана» берёт `bounds` минус 1 px.
- `focusable:false`, `skipTaskbar`, `alwaysOnTop('screen-saver')`, `setIgnoreMouseEvents(true,{forward:true})`.
- При смене мониторов/DPI окна не пересоздаются, а получают новые границы; снег пересэмплируется на новую ширину.
- Тестовый режим (`--scenario`, `--shot-after`) не берёт single-instance lock и может работать с отдельным профилем `--user-data=...`, чтобы не трогать настройки пользователя.

## Настройки
- `%APPDATA%\CozyWinter2\settings.json`. Запись атомарная (tmp → rename), предыдущая версия → `.bak`.
- Повреждённый файл переименовывается в `settings.json.corrupt-<время>`, затем берётся `.bak`, иначе значения по умолчанию.
- Санитайзер отбрасывает неизвестные ключи, исправляет типы, ограничивает диапазоны.

## Снег (этап 2)
- Высотная карта: колонка 2 px. Скрытый рельеф (шум + бугры + камни) виден только под снегом: видимая высота = снег + рельеф·smoothstep(0..4 px снега). Так голые камни не «торчат» прозрачными буграми.
- Поле неравномерности: низкочастотный fbm + 2–5 гауссовых «зон намётов» + 1–3 «проплешины», нормировано к среднему 1. Множитель накопления = lerp(1, поле, «Неравномерность»).
- Предел высоты мягкий: множитель 1 − (h/cap)², cap тоже немного зависит от поля.
- Осыпание: пары соседних колонок, перекладывание снега с верхней на нижнюю, пока перепад > tan(угла)·2 px. Основа не двигается → объём сохраняется точно.
- Ветер: проход по колонкам по ветру с «горизонтом тени» (11°). В тени (за буграми, шарами, декором — массив `obstacle`) переносимый снег оседает, на открытых местах рыхлый слой эродирует, наветренные склоны сильнее. Снег, вынесенный за край экрана, теряется (унесён).
- Свежий снег рыхлый (его переносит ветер), с постоянной времени ~150 с уплотняется и теряет 25% объёма.
- Тест-сценарий «60 с ускоренной симуляции» = 60 с × 20 = 20 минут снегопада, промотанные без рендера.
- Темп накопления: `DEPOSIT_K = 0.35` площади хлопья на осевшую снежинку; по умолчанию сугробы растут заметно за 10–30 минут.
- Колпак высоты зависит от поля плавно (`f/(f+1.2)`), без жёсткого clamp — иначе вершины сугробов превращались в плато.
- Число зон намётов/проплешин считается по плотности на ширину (≈1 на 480/560 px), а не «на 1920 px»: на узких экранах тоже есть разнообразие.
- Эрозия ветром ≈10%/с рыхлого слоя при сильном ветре: первая версия (≈80%/с) за 10 минут метели сдувала весь снег за край экрана.
- Снежная пыль с гребней — редкие мягкие размытые пятна, вытянутые по ветру (не больше ~220 частиц).
- Слой земли растеризуется программно (`willReadFrequently`) не чаще 5 раз/с: снег копится медленно, а сотни мелких команд на GPU стоили дорого.
- Дальние слои снега рисуются на отдельном холсте через кадр (двигаются < 1 px за кадр).

## Производительность (замер, i5-1135G7 / Iris Xe, 1920×1030, scripts/cpu-breakdown.ps1)
| режим | CPU всей машины (8 потоков) |
|---|---|
| пустой кадр 60 FPS (база Electron + композиция) | 2.0–2.8 % |
| снег по умолчанию, 60 FPS | 5.6–6.2 % |
| снег по умолчанию, 30 FPS | 2.5–3.0 % |
- Симуляция стоит 0.15 мс на шаг (< 1 % ядра) — почти всё уходит на отрисовку и композицию полноэкранного прозрачного окна в GPU-процессе Chromium.
- Пробовали и отвергли: `desynchronized` canvas (хуже, 8.2 %), пакетная отрисовка дальних хлопьев через Path2D (хуже вдвое: тесселяция путей в GPU-процессе).
- **Решение:** по умолчанию оставлено 60 FPS (плавность — основная цель), что на этом ноутбуке чуть выше 5 %. Режим 30 FPS укладывается в 3 %. На этапе 9 режим экономии будет автоматически переключать на 30 FPS (батарея/полноэкранные приложения).

## Проверки
- `--tray-check` нажимает реальные пункты меню трея (пауза, настройки, смена режима) и проверяет результат.
- Снимок рабочего стола делается через `desktopCapturer` (`--desktop-shot`): GDI BitBlt (даже с CAPTUREBLT) не видит прозрачные DirectComposition-окна Electron — первая проверка ошибочно показала «оверлея нет». Такие снимки содержат личный рабочий стол и в git не попадают (`tests/shots/desktop*.png` в .gitignore).

## Этап 3: уборка снега
- Снег — карта высот, поэтому инструмент-круг «срезает» всё, что выше нижней кромки круга (дыру в середине колонки сделать нельзя).
- Лопата: 55% снега толкается вперёд по ходу (валик в конце), 45% бросается «через плечо» за начало хода — так получаются валики по обе стороны чистой полосы. Объём сохраняется точно; у края экрана снег уходит на другую сторону.
- После хода лопаты — мгновенная локальная лавина (`settleAround`): без неё на месте валика несколько секунд стоял вертикальный столб (замечено на скриншоте, хотя числовые проверки проходили; в selftest добавлена проверка угла откоса).
- Снегодув уносит снег частицами-«носителями», которые возвращают объём туда, где упадут (за край экрана — теряется). Тепло растапливает (объём исчезает) с паром и каплями.
- «Очистить всё» — фронт порыва ветра проходит по экрану ~1.6 с.
- Undo/Redo: история (40 шагов) живёт в каждом окне-мониторе; main помнит порядок правок и отправляет Ctrl+Z/Ctrl+Y нужному окну.
- Оверлей никогда не получает фокус: Esc, Ctrl+Z/Y и цифры регистрируются как глобальные клавиши **только пока открыт интерактивный режим**, затем снимаются.
- Двойной клик определяется вручную (два нажатия < 450 мс): окно без фокуса получает dblclick ненадёжно.
- Док висит над сугробами (а не на панели задач), иначе закрывал бы снег и перехватывал движения инструментов у земли.
- Тесты ввода (`--input-test=…`) двигают настоящую мышь через `webContents.sendInputEvent`: клик по вкладке-снежинке → кнопка инструмента в доке → перетаскивание по снегу.

## Этап 4: снежные шары
- Свой решатель импульсов (без библиотек): 2 подшага × 10 итераций, накопленные импульсы, трение μ=0.9, упругость 0.18 только при сильном ударе, позиционная коррекция без добавления энергии.
- Сопротивление качению действует на оба тела контакта: по снегу 0.26, шар-шар 0.7 («снег липнет к снегу»). Без этого средний шар скатывался с нижнего при смещении 6 px (поймано тестом). Шар на снегу ещё и «пашет» его (затухание скорости) — иначе катился через весь экран.
- Спящее состояние: скорость < 7 px/с 0.35 с → шар «засыпает», не дрожит; спящий служит опорой как бесконечная масса; будится сильным ударом, захватом, или если пропала опора (проверка каждые 8 шагов — например, лопатой убрали снег).
- «Катать»: ком прокатывается по поверхности, снег в пятне контакта забирается из карты целиком (чистая полоса), площадь круга растёт ровно на собранную площадь; на максимальном радиусе 90 px снег больше не берётся (объём не теряется).
- Шапочка: хлопья, падающие на верх шара, наращивают «снежную шапку» до 0.3·r; при быстром качении она слетает облачком.
- Шары — препятствия для ветра (за ними растут намёты) и ловят хлопья (снег под шаром не копится).

## Этап 5: снеговик
- Сборка: шар T лежит на M, M на B, B на земле (`restsOn` из контактов решателя; спящие шары помнят опору), все три неподвижны ≥ 0.6 с, правила из ТЗ (`checkStack`). Причины отказа: `order` (размеры) → «Большой шар должен быть снизу», `crooked` (смещение) → «Поставьте шары ровнее», `limit`.
- Если средний шар опирается на склон сугроба, а не на нижний шар, это не стопка (законно) — поэтому тестовые сценарии ищут ровное место.
- Снеговик хранит реальные центры и радиусы своих шаров (малыш/великан), стоит на снегу и опускается, если снег под ним убрали; для шаров он — три статических круга, для ветра — препятствие, для хлопьев — ловушка (снег копится на шапке).
- Внешность — из ГПСЧ: шапка (ведро/цилиндр/вязаная), цвета шапки и шарфа, нос (морковка/длинная/пуговка), рот, 2–4 пуговицы, форма веток, иногда метла, в какую сторону смотрит. Имя из списка RU/EN.
- Живость: пружинное покачивание от ветра и касаний курсором, моргание каждые 2–6 с, взмах рукой, когда курсор ближе 170 px, фразы раз в 25–70 с (выключаются), шапка возвращается сама через 8 с после попадания снежком.
- Окошко кастомизации — DOM в окне оверлея; на время ввода имени окно оверлея временно становится фокусируемым (IPC `set-focus`), потом снова нет.
- Отрисовка каждый кадр (до 12 снеговиков × ~40 команд) — без кэша; тела шаров берутся из того же кэша спрайтов, что и снежки.

## Этап 6: снегоуборщик, время суток, декор
- Время суток: 6 пресетов с часами-«якорями» (рассвет 6:30, утро 9, день 13, закат 17, вечер 19, ночь 22). Каждая фаза держится, а за ~1.5 ч до следующей плавно (smoothstep) перетекает в неё; тест проверяет отсутствие скачков за сутки с шагом 0.01 ч. Режимы: авто (часы Windows), ручной, ползунок, демо (сутки за 60 с).
- Поверх рабочего стола небо по умолчанию НЕ закрашивается (`day.skyOpacity = 0`), а звёзды/луна/солнце/сияние приглушены (`celestial = 60%`) — иначе мешало бы работать. Тонирование времени суток применяется только к уже нарисованному (`source-atop`) — рабочий стол не темнеет. В отладочном окне небо непрозрачное.
- Светящееся (окна, фонарь, гирлянда, фары, маячок, отсвет снеговиков) рисуется ПОСЛЕ тонирования, режимом `lighter`.
- Снегоуборщик: срезает снег отвалом (оставляет 1.2 px) и выбрасывает его из жёлоба «вбок» — в боковом виде это глубина сцены, поэтому ~92% объёма уходит из профиля, ~8% падает порошей позади (первая версия бросала 40% назад и сама засыпала расчищенное). Снеговиков объезжает, уходя на задний план (меньше, выше, бледнее, рисуется за снегом), и не трогает снег под ними. Отвал толкает шары. По умолчанию выезжает раз в 8 минут (первый раз через 1.5 мин): с интервалом 3 мин сугробы не успевали вырасти.
- Ручное вождение — инструмент «Рулить» в доке: ←/→ (A/D) — ехать, ↑ (W) — быстрее, ↓ (S) — стоп, пробел — гудок. Клавиши — глобальные только пока выбран этот инструмент.
- Декор стоит основанием на земле и рисуется до снега, поэтому сугробы естественно его заносят. Снег ложится на крышу полностью, на ёлки и забор — частично (хвоя и щели пропускают снег: иначе за забором никогда не было бы снега). Декор — препятствие для ветра (намёты за домиком) и для шаров. Перетаскивается только «Рукой» в режиме инструментов, чтобы в обычном режиме не мешать кликам по рабочему столу. «Ёлка» ставит новую ёлку (до 20).
- В тестах снега/шаров/снеговиков снегоуборщик и декор выключены (у них свои проверки).

## Этап 7: дополнительные фишки
- Следы: инструмент «Шаги» вдавливает снег (объём выдавливается в бортики — сохраняется) каждые ~24 px и рисует отпечаток на кромке; новый снег его заметает (прозрачность по слою, выпавшему сверху), если снег убрали — отпечаток исчезает. «Снежный ангел» — широкий штамп-отпечаток с силуэтом.
- Снежковый бой: «оттяни и отпусти» (рогатка с пунктиром траектории). Снежок летит по дуге и одновременно «к зрителю» (z 0→1 за 0.85 с, растёт в размере); по пути может попасть в снеговика (вздрагивает, роняет шапку — она лежит рядом 8 с и возвращается) или в шар (толкает); долетев — шлёпается о «стекло»: клякса с подтёками медленно сползает и за ~24 с тает. Если упал в снег раньше — пуф и чуть снега.
- «Снежный шар»: 55% снега поднимается частицами-носителями объёма, кружит ~2.6 с вокруг разных центров и оседает обратно (тест: ≥ 90% объёма возвращается; остальное — за край экрана). Шапки снега на шарах, снеговиках и декоре слетают.
- «Зима за минуту»: время сцены ×25 на 60 с (кнопка в доке), до 200 шагов симуляции за кадр.
- Фотоаппарат: монитор под курсором через `desktopCapturer` (рабочий стол вместе со снегом) → `Изображения\CozyWinter\CozyWinter-<дата>.png`; в отладочном окне — само окно. Уведомление Windows.
- Звук: WebAudio, всё синтезируется. По умолчанию выключен; громкости: общая, ветер, эффекты, мотор. Фоновые звуки играет только окно основного монитора (не удваиваются). Проверено, что движок создаётся (`running`) и все события играются без ошибок; на слух в этой среде проверить нельзя.
- Снег на краях окон — **сделан, но выключен по умолчанию** (рисуется над чужими окнами и зависит от внутренностей Windows; включается в настройках «Сцена»).
  - Помощник Windows API: EnumWindows + DWM (рамка без тени, «скрытые» окна других рабочих столов), отсечение кромок окнами выше по z-порядку, SHQueryUserNotificationState + проверка «активное окно = весь монитор» для автопаузы.
  - Сначала был PowerShell-скрипт с C#-вставкой: на этой машине голый старт `powershell.exe` — 9 с, до первого ответа ~20 с. Теперь тот же C# при первом запуске компилируется встроенным в Windows `csc.exe` (.NET Framework 4, есть в Windows 10/11) в маленький `cozywin-helper-2.exe` в папке профиля (~1 с), дальше стартует мгновенно (1.2 с до первых данных вместе с компиляцией). PowerShell остался запасным путём.
  - Окна самого Cozy Winter помощник пропускает. Развёрнутые окна (кромка у верха экрана) — тоже.
  - Проверено на настоящем окне другого процесса (`--ledge-test`, снимок рабочего стола — только локально): снег лежит над заголовком, только на видимой части кромки. Осыпание при перемещении/закрытии — юнит-тестом.

## Этап 8: управление
- Док — DOM внутри окна оверлея основного монитора (в отладочном окне — там же). В свёрнутом виде — круглая «снежинка» внизу по центру; док раскрывается по клику на неё, в режиме инструментов или по `Ctrl+Alt+S`; без режима инструментов прячется через 2.5 с после ухода курсора (автоскрытие отключается в настройках). Перетаскивается за «ручку» слева, позиция запоминается.
- Док висит над сугробами (≈ 1.15 × макс. высоты сугроба + 34 px от земли). В маленьком окне 1280×720 высокие снеговики могут оказаться за доком — док можно перетащить или он скроется.
- Подсказки у кнопок — свои (title-подсказки в окне без фокуса ненадёжны), с горячей клавишей.
- Цифровые/буквенные клавиши инструментов работают только в режиме инструментов (глобальная регистрация на это время). Одиночные буквы нельзя назначить глобальной клавишей в настройках (иначе они перехватывались бы во всех программах) — только с Ctrl/Alt/Shift или F1–F12.
- Окно настроек: 8 вкладок, живой предпросмотр (та же симуляция в миниатюре, сугробы масштабированы под 150 px), «Сбросить» в каждом разделе, пресеты сверху, редактор пресетов каждой фазы суток (выбор фазы сразу показывает её на экране), статус регистрации горячих клавиш («⚠ занято»), экспорт/импорт JSON.
- Подсказка первого запуска — 3 карточки над доком; после «Понятно» `firstRun=false`, можно показать снова из «Системы».
- Проверено на настоящем оверлее зондом WindowFromPoint (`--mouse-test`): пассивный режим — клик уходит окну под оверлеем; режим инструментов — оверлею; после Esc — снова насквозь; курсор над снежинкой дока — оверлею; отвёл — насквозь.
- Сами глобальные сочетания в тестах не нажимаются (клавиши ушли бы в активное окно пользователя) — проверяется их регистрация и переназначение.

## Этап 9: система и упаковка
- Автопауза: помощник Windows API сообщает «полноэкранно» (SHQueryUserNotificationState = D3D/презентация или активное окно накрывает весь монитор). Оверлеи прячутся (иначе висели бы поверх игры) и останавливают цикл. Проверено настоящим полноэкранным окном другого процесса (`--system-check`).
- Экономия: `auto` — от батареи (`powerMonitor`), `on` — всегда: 30 FPS и −30% снежинок.
- Автозапуск: `app.setLoginItemSettings` (ключ HKCU\...\Run). В режиме разработки не трогается (в автозапуск попал бы голый electron.exe); для portable берётся путь исходного exe (`PORTABLE_EXECUTABLE_FILE`).
- Сцена сохраняется раз в минуту и при выходе (окна получают `saveNow`, выход ждёт 0.7 с): снег и рыхлость по колонкам (0.1 px), шары, снеговики с внешностью и именами, декор, следы. Ключ — геометрия монитора; при другой ширине снег пересэмплируется, объекты масштабируются по x.
- Иконка рисуется кодом (`scripts/make-icon.mjs`): PNG и ICO без сторонних библиотек.
- electron-builder: NSIS (без прав администратора, с выбором папки, ярлыки) и portable; `static/winhelper.*` распаковываются из asar (их читает csc/PowerShell).
- Этапы 7–9 разрабатывались вместе (общие main.ts/overlay.ts/selftest), поэтому закоммичены одним коммитом после общего прогона проверок.
- selftest: если запуск вообще ничего не вернул (бывало один раз из ~20 под сильной нагрузкой машины, повторно не воспроизводилось), делается один повтор — с пометкой «(повтор)» в выводе, чтобы это было видно.

## Упаковка (факт)
- Собрано: `D:\CozyWinter2\release\CozyWinter2-Setup-1.0.0.exe` (121 МБ) и `CozyWinter2-Portable-1.0.0.exe` (110 МБ). На C: не хватило места (0 МБ свободно) — по разрешению пользователя сборка выведена на D: (`scripts/dist.mjs --out=…`).
