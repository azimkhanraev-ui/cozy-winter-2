# Решения (DECISIONS)

Сюда записываются решения, принятые без вопросов к заказчику.

## Окружение
- **Node.js на машине не был установлен**, а `winget install OpenJS.NodeJS.LTS` завис на загрузке (сеть ~10–20 КБ/с) и завершился с ошибкой. Для разработки использован Node из VS Code (`Code.exe` с `ELECTRON_RUN_AS_NODE=1`, Node v24) и npm 12, скачанный отдельно (шимы в `%LOCALAPPDATA%\cozy-tools`). Пользователю для `npm start` нужен обычный Node.js LTS.
- **Electron зафиксирован на 45.4.1**: его zip уже лежал в `%LOCALAPPDATA%\electron\Cache`, иначе пришлось бы качать ~150 МБ.
- `scripts/start.mjs` удаляет `ELECTRON_RUN_AS_NODE` из окружения перед запуском Electron, иначе он стартовал бы как Node.

## Сборка
- esbuild (без vite): main/preload → CJS, рендереры → IIFE. Типы проверяет `tsc --noEmit` (`npm run typecheck`).
- Зависимостей в рантайме нет, только devDependencies: electron, electron-builder, esbuild, typescript, vitest.

## Архитектура
- `src/sim/` — чистый TS: ГПСЧ/шум, ветер, снегопад, высотная карта, сцена. Без DOM и Electron, покрыт vitest.
- `src/render/` — Canvas 2D: спрайты (offscreen canvas), снег на земле, хлопья.
- `src/main/` — Electron: окна, трей, настройки, IPC.
- `src/ui/` — рендерер-страницы (оверлей, настройки).
- `src/shared/` — схема настроек и типы IPC (чистые, используются обеими сторонами).
- Фиксированный шаг симуляции 1/60 с; рендер может идти на 30 или 60 FPS.

## Оверлей
- Окно = `workArea` монитора (без панели задач). Если `workArea` совпадает со всем экраном (панель скрыта), высота уменьшается на 1 px, чтобы Windows не считал окно полноэкранным. Опция «Земля = низ экрана» берёт `bounds` минус 1 px.
- `focusable:false`, `skipTaskbar`, `alwaysOnTop('screen-saver')`, `setIgnoreMouseEvents(true,{forward:true})`.
- При смене мониторов/DPI окна не пересоздаются, а получают новые границы; снег пересэмплируется на новую ширину.
- Тестовый режим (`--scenario`, `--shot-after`) не берёт single-instance lock и может работать с отдельным профилем `--user-data=...`, чтобы не трогать настройки пользователя.

## Настройки
- `%APPDATA%\CozyWinter2\settings.json`. Запись атомарная (tmp → rename), предыдущая версия → `.bak`.
- Повреждённый файл переименовывается в `settings.json.corrupt-<время>`, затем берётся `.bak`, иначе значения по умолчанию.
- Санитайзер отбрасывает неизвестные ключи, исправляет типы, ограничивает диапазоны.

## Снег (этап 2)
- Высотная карта: колонка 2 px. Скрытый рельеф (шум + бугры + камни) виден только под снегом: видимая высота = снег + рельеф·smoothstep(0..4 px снега). Так голые камни не «торчат» прозрачными буграми.
- Поле неравномерности: низкочастотный fbm + 2–5 гауссовых «зон намётов» + 1–3 «проплешины», нормировано к среднему 1. Множитель накопления = lerp(1, поле, «Неравномерность»).
- Предел высоты мягкий: множитель 1 − (h/cap)², cap тоже немного зависит от поля.
- Осыпание: пары соседних колонок, перекладывание снега с верхней на нижнюю, пока перепад > tan(угла)·2 px. Основа не двигается → объём сохраняется точно.
- Ветер: проход по колонкам по ветру с «горизонтом тени» (11°). В тени (за буграми, шарами, декором — массив `obstacle`) переносимый снег оседает, на открытых местах рыхлый слой эродирует, наветренные склоны сильнее. Снег, вынесенный за край экрана, теряется (унесён).
- Свежий снег рыхлый (его переносит ветер), с постоянной времени ~150 с уплотняется и теряет 25% объёма.
- Тест-сценарий «60 с ускоренной симуляции» = 60 с × 20 = 20 минут снегопада, промотанные без рендера.
- Темп накопления: `DEPOSIT_K = 0.35` площади хлопья на осевшую снежинку; по умолчанию сугробы растут заметно за 10–30 минут.
